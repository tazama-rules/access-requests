# Tazama rules & configuration - access requests

The Tazama rule processors and full configuration source live in private repositories. Read-only copies are available to community members through this organization ([tazama-rules](https://github.com/tazama-rules)), mirrored from the canonical `frmscoe` repositories at every release.

## Do you actually need access?

| I want to... | You need |
| --- | --- |
| **Run the full Tazama system** | No access needed - pre-built images are public on [DockerHub (tazamaorg)](https://hub.docker.com/u/tazamaorg), and the deployment tooling is in the public [tazama-lf](https://github.com/tazama-lf) org |
| **Deploy the full configuration for an implementation** | Read access here - [request it](../../issues/new/choose) |
| **Inspect the rule processor source code** | Read access here - [request it](../../issues/new/choose) |
| **Contribute to the rules or configuration** | Membership of the `frmscoe` org - start with a [request here](../../issues/new/choose) and note that you want to contribute |

## How it works

1. Open an [access request](../../issues/new/choose) - a short form, takes a minute. Use the GitHub account that should receive access.
2. A maintainer reviews it (we usually cross-check with the [Tazama Slack](https://www.tazama.org/slack-access/)).
3. On approval, you'll receive an invitation to the `tazama-rules` organization on the account that filed the request - accept it and you have read access to all mirrors.

Access is read-only. The mirrors carry the released `main` branch and tags, refreshed at each release. Issues and pull requests on the mirrors are disabled - to report problems or contribute, ask in Slack or note it in your access request.
